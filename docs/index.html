Native FortiOS path

Run the appliance and verify real traffic.

Run authorized FortiOS 7.6.8 for KVM in QEMU inside Docker. A practice client and a DMZ web server make policy decisions observable in the native interface and Forward Traffic logs.

  • Linux x86-64 or WSL 2 with /dev/kvm and /dev/net/tun
  • Docker Engine 28+ and Docker Compose 2.36+
  • FortiGate-VM64 for KVM from Fortinet Support and an authorized activation

Docker worksheet

Practice policy logic without a VM image.

Run three focused exercises covering a scoped HTTP rule, an ordered exception, and a custom TCP service. The checker reports the expected rule and the first rule that actually matches.

docker compose -p fortigate-worksheet \
  -f training/compose.yaml up -d --build

Open http://practice.localhost:18846/training/ on the Docker host. This path needs Docker and the Compose plugin, and does not need a FortiOS image or Fortinet account.

What to test in FortiOS

Forwarding and logs

LAB-LAN-DMZ-HTTP permits TCP 80. LAB-LAN-DMZ-DENY-8080 denies TCP 8080. Run bash scripts/verify-forwarding.sh from deploy, then compare the matching events in Log & Report > Forward Traffic.

LABCO company profile

Load 12 synthetic users across four departments, six user groups, one RADIUS server, six IPv4 address objects, and three address groups into the native FortiOS tables. The profile uses LABCO-prefixed names so learners can inspect and remove its objects.
